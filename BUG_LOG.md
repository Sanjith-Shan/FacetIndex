# Bug log

Every bug found while building FacetIndex, in the order found, with the tool or check that caught it.

| # | Milestone | Bug | Found by | Fix |
|---|---|---|---|---|
| 1 | M0 | `AttributeStore.insert` on a row that was already live rewrote the row's tag array but never updated the per-tag bitmaps, so a bitmap could list a row that no longer carried the tag | JUnit model test: the store against a `HashMap` model under 5,000 random insert, delete and `setAttrs` operations | Insert on a live row now goes through `setAttrs(row, new, current)`, which updates both sides |
| 2 | M0 | The two Kotest property tests for the SIMD kernel were written as expression bodies (`= runBlocking { ... }`), so they returned a non-`Unit` value and JUnit 5 silently skipped them | Reading the test report: the tests were missing from the PASSED list | Declared `: Unit` and ended the block with `Unit`; both now run and pass |
| 3 | M2 | k-means++ seeding on 500k points ran for over 15 minutes at under one core: the Kotlin distance loops kept the Vector API species in an instance field, so C2 could not treat it as a constant and the vector code fell back to its slow, allocating path | Watching the build log stall and the process CPU time in Task Manager | Moved the float kernels (`dot`, `f32`) into `L2.java`, where the species is a `static final` constant |
| 4 | M4 | An item inserted through the gRPC API (or any insert whose row is outside the base file) crashed S0 with an out-of-bounds read: the vector store was the mapped base file only, so the new row's vector did not exist anywhere the exact strategies could read it | gRPC service test (upsert, then search for the upserted vector); found only after wrapping service errors as `INTERNAL` with the cause, since gRPC reported a bare `UNKNOWN` | `OverlayStore` holds vectors that are not in, or differ from, the base file; the applier writes to it |
| 5 | M0 | CI could not compile: the `.gitignore` line `data/` (meant for the local data directory) also matched `src/main/kotlin/facetindex/data/`, so the format readers were never committed. The first CI run had also failed because `gradlew` was committed without the executable bit | GitHub Actions build log (`Unresolved reference 'data'`, then `./gradlew: Permission denied`) | Anchored the ignore rules (`/data/`, `/build/`) and set the executable bit in the index |
| 6 | M1 | The CI smoke step failed with `syntax error: unexpected end of file` in `scripts/fi.sh`: files rewritten by Python on Windows had CRLF line endings, which bash on Linux rejects | GitHub Actions log | `.gitattributes` with `* text=auto eol=lf`; every tracked text file normalized |
| 7 | M2 | The first pass over the 10M index ran at a few queries per second, and QPS depended on the order of configurations: the static benchmark kept two copies of the 1.92 GB vectors hot (Lucene's `.vec` for S2/S3 and the raw `.u8bin` for S0/S4/S6) on a box where the shared WSL VM already held 4 to 6 GB, so the page cache thrashed | Phase timings added to the sweep (the S2 warm-up took 484 s for 2,000 queries) and the Windows available-memory counter | Exact strategies now read the vectors from Lucene's own `.vec` file (signed int8 kernel `L2.i8`, query shifted once per search), checked row by row against the base file at load; every sweep also runs a global warm-up |
